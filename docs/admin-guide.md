# Руководство администратора

## Дефолтный доступ

После первого запуска:
- логин: `admin`
- пароль: `00000`

Если нужно вернуть пароль администратора к дефолтному:

```bash
./scripts/reset-admin-password.sh
```

## Основные задачи администратора

Администратор управляет:
- пользователями и правами
- справочниками отделов, кабинетов, принтеров и моделей картриджей
- уведомлениями по остаткам
- журналом действий
- отчётами
- резервным копированием и обновлением системы

## Пользователи и права

В системе есть роль как шаблон и индивидуальные права как финальное состояние.

Типовой сценарий:
- выбрать роль
- проверить автоматически подставленные права
- включить или отключить нужные чекбоксы
- сохранить пользователя

Можно тонко настроить:
- просмотр и редактирование каталога
- операции с картриджами
- просмотр логов
- экспорт отчётов
- управление пользователями
- настройку порогов
- ручной ввод даты и времени

## Журнал и аудит

Журнал фиксирует:
- входы в систему
- создание и изменение пользователей
- операции по картриджам
- создание, изменение и вывод из эксплуатации принтеров
- действия с отделами и кабинетами

Для записей аудита доступны:
- пользователь
- тип действия
- сущность
- результат
- старые значения
- новые значения

## Управление остатками

Администратор должен следить за:
- минимальными остатками
- резервом
- моделями, которые уходят в дефицит
- корректностью привязок принтеров к кабинетам

Рекомендуемый ритм:
- ежедневно смотреть обзор и уведомления
- еженедельно проверять журнал и отчёты
- регулярно выгружать backup

## Обновление

Штатное обновление:

```bash
./scripts/update.sh
```

После обновления стоит проверить:
- `./scripts/check-health.sh`
- вход под `admin`
- разделы `Принтеры`, `Картриджи`, `Отчёты`

## Backup и restore

Ручной backup:

```bash
./scripts/backup-db.sh
```

Восстановление:

```bash
./scripts/restore-db.sh backups/<backup-file>.sql
```

Автоматическая ежедневная установка backup в `cron`:

```bash
./scripts/install-backup-cron.sh
```

## Где смотреть текущее состояние

Полезные команды:

```bash
docker compose ps
docker compose logs -f backend
docker compose logs -f frontend
docker compose logs -f postgres
./scripts/status.sh
./scripts/check-health.sh
./scripts/smoke-test.sh
```

## Безопасность

Перед продом обязательно:
- изменить `APP_JWT_SECRET` в `.env`
- задать свой `POSTGRES_PASSWORD`
- сменить дефолтный пароль `admin`
- ограничить внешние порты firewall-правилами

Ускоренный сценарий подготовки:

```bash
./scripts/prepare-release-env.sh --write --rotate-admin-password --install-backup-cron
docker compose up -d --build
./scripts/release-check.sh --with-backup
```

Если backend не нужен снаружи, публикуй только frontend.
